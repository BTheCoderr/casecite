# Patent review reports (development preview)

Based on PR #14 and the verified #12/#11/#8 lineage. Do not merge the alternative #9/#10 implementations.

The new POST /api/v1/patent-workspaces/{workspace_id}/report endpoint requires DEBUG, contracts.use, existing workspace access, current matter membership and an explicit fictional_data_only=true request. The frontend buttons appear only in Vite development with VITE_PATENT_REPORT_PREVIEW_ENABLED=true. They export saved workspace data, not unsaved changes. Report generation is in memory, audited as DATA_EXPORT, and uses existing python-docx and ReportLab dependencies. No AI, external requests or migrations. Static filenames and no-store response. All claim mappings are described as unverified, regardless of client fields or stored flags. PDF has a page footer; Word has a repeating header and footer. Reports include disclosure version/hash, entered claim mapping details, manual Office Action notes stored in the disclosure, practitioner notes and review gates. Separate local prior-art and Office Action workbench exports remain JSON; no automatic cross-workspace data transfer. The disclosure hash is not an approval of the report or chart. Saved multi-part workspace updates are not atomic; concurrent edits should be avoided during preview exports.

The preview limits report text to 180,000 characters and rejects unsupported WinAnsi PDF characters; use Word for other scripts. It never silently truncates the report. Exported files are not encrypted. No real client data or production enablement. Before release, test real browser downloads, pagination/long text, authorization revocation, concurrent edits and human approval tied to a complete report hash; ensure retention/hold and offboarding are reviewed. CI and live runtime still required.
